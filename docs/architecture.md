# 架构说明

## 运行边界

浏览器负责交互、场景渲染和调试表单，FastAPI 服务持有权威状态。NPC Agent 读取经可见性过滤的上下文，生成候选回复与行动意图；生成成功不等于状态已提交或游戏行动已完成。

当前运行时是单机文件后端，不需要 Redis、PostgreSQL 或向量数据库。海滩地图由 Phaser 程序化绘制，移动与采集结果由服务端确认。

| `core/conversation/` | 成员资格、送达、意愿与发言机会调度 |
| `core/hooks/` | 有角色范围、事件依赖、优先级和预算的上下文注入 |

## 状态与知识

`WorldState` 汇总世界代次、revision、分域状态、事件、知识索引、消息、回执、AgentState、Hooks、记忆及海滩状态。报告经过来源许可、版本、序号、实体引用和载荷验证后提交。

知识属于实际观察或接收信息的角色。事件参与者不会仅因出现在事件中就自动知情；群聊新成员也不会自动获得入群前的消息。物品、位置、群体和生产项按 `visible_to` 过滤；没有明确可见性时不默认公开。角色上下文不包含其他 NPC 的私人身体和需求状态。

## 生成与提交

会话缓存按命名空间、世界、NPC、会话和运行代次隔离。缓存超时只回收 Agent 实例，已确认状态仍保存在世界聚合中。

一次模型回合使用角色配置与可见信息构造候选状态，然后校验结构化输出、发言身份、行动意图与依赖。只有提交检查通过后，候选 AgentState 与回复才成为确认状态；模型失败、取消或旧代次结果不能直接覆盖当前世界。流式接口提供文本增量、最终结果或错误事件，增量文本本身不是提交回执。

生成 Agent 不配置执行工具。`core/game/capabilities.py` 登记受限行动能力，执行路径负责校验和回执。通用移动、跟随等能力目前包含模拟接受结果，不能据此认定场景里已完成对应物理行动。

## 记忆与上下文

记忆归属于特定世界和 NPC，保留事件来源、可信程度与访问状态。检索基于关键词和重要性排序；压缩将事实、传闻、约定与来源组织成结构化候选，并验证来源依赖。这里没有 Embedding、向量库或已验收的通用语义记忆引擎。

Hooks 是显式登记的上下文提供者。激活实例记录触发事件与 NPC 范围，装配时受范围、依赖和预算约束。读取状态上下文与真正执行模型回合是不同操作，不能假定所有读取接口都会进行记忆检索或模型调用。

## 持久化与恢复

世界仓库以进程内锁保护候选聚合，在同目录写临时文件、flush、fsync 后使用 `os.replace` 替换，再发布确认内存版本。回执、消息和知识与世界状态处于同一个聚合提交边界。存储根文件锁阻止第二个写入器。

存档复制世界聚合并计算 SHA-256 校验和，读取时验证结构版本和内容版本。恢复替换世界状态并生成新 `run_epoch`，后续提交须验证当前代次。快照不包括外部模型服务、浏览器状态、进程内诊断缓冲或整个磁盘目录。

当前保证限于单进程、单机文件替换，不覆盖分布式事务、多个文件之间的事务或断电后的目录元数据持久性。聚合历史和回执的长期容量仍需评估。
