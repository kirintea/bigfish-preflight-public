# NPC-Agent 核心设计：群聊、性格发言、记忆与 Hooks

初稿日期：2026-11-14。公开修订：2026-11-15。

## 1. 范围与目标

本文专门记录 NPC-Agent 的会话、发言意愿、记忆、压缩、遗忘和提示词扩展设计，作为能力扩展、内容设计与体验评估的依据。

设计目标：

- 支持多个 NPC 之间的群聊，玩家可以不参与。
- 角色之间的身份、发言、知识、关系和记忆不能混淆。
- 群聊协调与上下文扩展采用明确的模块边界，允许独立演进。
- 预留特殊事件、节日等提示词注入 Hooks。
- 核心记忆需要考虑压缩、遗忘与后续调用。
- NPC 发言应随性格与情况变化：有的健谈，有的话少、怕生；允许听别人说了几句后才参与。
- “别人说三句话之后才说一句”是表现举例，不是必须执行的固定配额。

**本文描述目标机制、约束与候选方案，不是已实现功能或验收结果清单。** 当前原型已有群聊、Hooks、记忆与存档等实现；实际支持范围与限制以运行文档为准。本文不承诺并发人数、调用费用或性能。

## 2. 目标体验

NPC 不需要每轮都发言，也不需要每个人平均分配台词。

我们希望出现这样的表现：熟人之间自然接话，怕生者在陌生人面前先听；安静的人遇到熟悉的话题会主动补充；忙碌、疲惫或心情不好时减少闲聊；共同经历能影响话题和态度，但不会每次见面都复述同一段往事。

“记住”应该体现为合适的回应、信任变化、履行约定和后续选择，不只是把日志原文塞给模型。“忘记”应该有范围和过程，而不是随机删除人物身份、有效任务和关键关系。

## 3. 模块分工与运行循环

| 模块 | 核心职责 | 边界 |
|---|---|---|
| 世界事件与规则 | 确认实际发生的行动、发言、听闻、关系和承诺 | 保存权威结果，不依赖摘要推断已经完成的事 |
| 会话协调器 | 管理会话成员、模式、发言机会、顺序和结束条件 | 不要求存在玩家，不允许角色在两处同时占用主动发言轮次 |
| 发言意愿评估 | 结合性格、关系、话题和状态，决定是否值得发言 | 使用有界规则评分与抽样；不为每个沉默 NPC 逐帧调用模型 |
| 个人记忆服务 | 写入获知的事件，压缩、检索、衰减与维护来源 | 每个世界、人物独立；不把私有记忆拼成全员共享上下文 |
| Hook 组装器 | 收集当前有效的事件、节日、场景及人物片段 | 过滤知情范围，限制长度与权限，记录来源和版本 |
| 角色生成器 | 为指定人物生成这一轮台词及受限意图 | 不替其他角色或玩家做决定 |
| 提交与记录 | 检查有效性，确认实际传达和规则效果 | 生成成功不等于说出口，受理不等于动作完成 |

建议运行顺序：

1. 一条发言实际传达、一个相关事件发生，或出现允许的搭话机会。
2. 协调器确认哪些人物仍有资格参与。
3. 评估发言意愿，选择一个人物，或者选择暂时无人发言。
4. 为该人物检索记忆、应用有效 Hooks、组装受限上下文。
5. 生成并检查回复，再确认是否实际说出及谁实际收到。
6. 按结果写入记忆、关系或承诺，决定继续、换话题或结束。

## 4. 群聊的身份、成员与消息

### 4.1 会话记录

建议至少包含世界 ID、世界运行代次、会话 ID、模式、话题、发起者、位置或渠道、成员列表与成员版本、当前轮次、消息序号、状态与结束原因。

人物用稳定 ID 标识，名字和昵称只用于表现。同名或改名不改变记忆与关系归属。玩家是可选成员，玩家成员为空不影响 NPC 会话成立。

### 4.2 消息记录

每条消息独立记录：作者、指向的对象、回复哪条消息、实际接收者、游戏时间、会话序号、正文、关联意图和提交状态。

必须分清：

- 甲在对乙讲话。
- 丙是否在场、能够听见并实际接收到这句话。
- 玩家界面是否允许展示这句话。
- 这句话中提出的主张是否被游戏事实支持。

其中任何一项都不能代替其他项。听到“甲说仓库有木头”，首先得到的是一份有来源的说法，不自动证明库存确实有木头。

### 4.3 逐个发言者生成

建议每轮只指定一名 NPC。该轮只提供此人的设定、知识和可见历史，其他成员以该人物可知的公开信息出现。

模型可以引用别人已经说过的话，但不能生成一段全员剧本后把每个人的台词当成已经发生。输出如带发言者 ID，必须匹配请求绑定的身份。

成员中途加入不自动获得旧历史；可以由他人真实转述。成员退出、失去说话能力或离开有效渠道后，相关待提交回复必须重新检查或失效。

## 5. 性格与当前状态分开建模

下表是候选设计维度，不是现实人格测量工具，也不是要求每个角色填满的数值表。

| 维度 | 影响的表现 | 需要避免的误解 |
|---|---|---|
| 主动社交倾向 | 是否主动开始谈话、参与新话题 | 主动不等于每句都抢话 |
| 陌生人拘谨程度 | 不熟悉的成员增加时是否更谨慎 | 怕生不等于没有观点或缺少能力 |
| 熟人舒适程度 | 与信任对象交谈时是否更放松 | 熟悉和信任不是完全相同的关系 |
| 接话倾向 | 听到相关内容时是否愿意补充 | 接话频率与主动搭话频率可不同 |
| 表达长度倾向 | 倾向简短、适中或详细 | 话少不等于每句话都短，话多也不必长篇 |
| 打断倾向 | 是否倾向插入重要信息 | 需服从实际轮次机制，不并发覆盖别人的发言 |
| 隐私与自我披露倾向 | 愿意谈多少自己的经历 | 愿意分享仍不能越过内容规定的秘密范围 |
| 话题兴趣与专长 | 哪些内容更容易引起回应 | 专长不授予角色尚未获得的事实 |

性格维度与固定背景属于内容定义。关系、熟悉程度、情绪、疲劳、工作忙碌、当前目标等属于可变状态，不能都压进一句“这个人内向”。

性格可以保留受剧情影响的弹性部分，但单次模型回复不直接改写长期人格。若未来支持演化，应由有来源、有限幅度的规则单独处理。

## 6. 动态发言意愿与概率

### 6.1 分开评估四件事

1. **主动开口**：是否想发起一个话题或邀请别人交谈。
2. **接话补充**：听过别人发言后，是否有相关内容想说。
3. **被问回应**：被点名或直接提问时，如何回答、拒绝、犹豫或保持沉默。
4. **表达方式**：决定发言后，说多长、对谁说、使用什么语气。

不能只用一个全局“话多概率”同时控制以上行为。

### 6.2 先检查资格，再评估意愿

无论概率多高，人物不在有效渠道、无法说话、没有获得相关信息、已被其他主动会话占用，或者世界不允许本轮推进时，都不进入普通发言候选。

通过资格检查后，考虑以下因素：

- 基础性格与主动、接话倾向。
- 与在场者的熟悉、信任和紧张关系。
- 话题兴趣、当前目标、与自身相关程度。
- 是否被点名、是否存在尚未回应的问题。
- 最近是否已经说过很多话、是否重复表达同一意思。
- 疲劳、情绪、忙碌、社交负担。
- 已经听了几轮、是否等到了合适的接话位置。
- 当前节日或事件带来的有界临时修正。

建议将这些因素转换为受限的“本次机会发言意愿”，再抽样决定是否报名，协调器从报名者中选择一位。允许所有人都不报名；此时可以短暂停顿、等待新事件或结束闲聊，而不是强行让某人发言。

### 6.3 概率的计算单位

概率按明确的发言机会评估，例如一条相关消息实际传达之后、话题切换时或收到新的交谈触发。不能按画面帧率反复抽样，也不能对同一个机会无限重试直到某人“中奖”。

每个机会有 ID。保存所选人物与抽样结果，重试沿用结果，避免网络重试变成重新选人。用于可复现调试的随机状态按世界或会话隔离。

初期不固定通用百分比。先定义评估单位与可观察表现，再通过不同性格、关系和人数的场景校准分布。

### 6.4 “别人说了几句才开口”的实现含义

可以保留“上次发言后实际听过的相关轮次数”。它对接话意愿形成有限加成，但不能无限累积并强迫沉默人物发言。

话少、怕生的 NPC 可能连续听几轮，等熟悉的话题或信任对象出现后补上一句；也可能整场只听。被直接问到时，可以立即简短回答，不必为了满足间隔机械等待三句。

角色说完后，接话冷却或短期话题饱和提高；如果出现新的直接问题或重要信息，可以按规则重新获得回应机会。公平调度只避免健谈者长期霸占，不要求每个人平均分配台词。

### 6.5 直接提问与沉默

直接问题进入专门的待回应状态，给予被问者优先回应机会，而不是永远交给普通闲聊抽样。

优先回应不等于强制服从请求。结果可以是回答、拒绝、表示不愿讨论、可见的犹豫或沉默反馈。玩家正式对话不能因为“怕生所以抽样未命中”而永久卡住；始终提供继续、换话题或结束入口。

### 6.6 临时情境与长期性格

节日可以提高搭话意愿、增加某个话题的相关性；争执可以降低自我披露、提高戒备。此类修正有作用域和有效期，不能让所有角色变成同一种健谈人格。

建议让角色在熟悉程度和状态改变时逐步变化，避免同一场对话中每轮从极端沉默跳到极端热情。具体平滑方式与数值待验证。

## 7. 会话节奏与暂停

| 情况 | 建议行为 |
|---|---|
| NPC 自主聊天 | 世界继续运行，生成按机会调度，角色可以忙碌、离场或终止 |
| 玩家进入正式对话 | 世界暂停，会话内仍可以按轮次交流并确认语义结果 |
| 玩家只是旁听 | 不自动切入正式模式，知识仍以实际接收为准 |
| 手动暂停、闲置或离线 | 自主群聊停止推进，保存已确认消息和状态 |
| 正式对话结束 | 恢复此前状态，保留其他仍有效的暂停原因 |

建议采用不同的时间基准：

- 生活变化、长期记忆衰减、节日阶段与 NPC 自主活动：游戏时间。
- 正式对话中的接话机会、重复话题饱和、短期会话节奏：已确认的对话轮次。
- 模型超时、界面等待与服务限额：真实时间。

这样不会因为世界暂停而让正式对话永远处于发言冷却，也不会因为玩家离线一晚而偷偷遗忘一整晚的游戏经历。真实时间的显示间隔只控制阅读节奏，不重复产生游戏效果。

## 8. 记忆内容与存储层次

“记忆”不是一份不断增长的聊天文本。建议区分以下内容：

| 类别 | 保存什么 | 保留原则 |
|---|---|---|
| 固定人物定义 | 身份、硬背景、长期表达倾向 | 版本化内容，不进入普通遗忘 |
| 世界权威事实 | 已执行结果、资源、任务、关系 | 由游戏保存，不因 NPC 忘记而撤销 |
| 当前工作记忆 | 近期可见发言、当前话题、未回答问题 | 短窗口，结束或超预算后整理 |
| 个人情景记忆 | 曾亲历或听闻的事件、人物、结果 | 按意义与后续关联保留或降权 |
| 长期认知与偏好 | 对人和事的稳定认识及来源 | 可被新证据修订，不能从一句话无依据推导人格 |
| 有效承诺与关键关系 | 约定、尚未结束的任务、关键关系节点 | 活跃期间受保护，结束后转为历史 |
| 摘要与检索索引 | 压缩描述、主题标签、检索特征 | 派生数据，可重建，不能替代事实来源 |
| 原始记录归档 | 必要的原话与事件证据 | 独立容量策略，不要求永久保存每句闲聊 |

这些是逻辑职责划分，不要求部署多个数据库或采用固定“四层架构”。当前使用文件持久化、关键词与重要性检索及结构化规则压缩，具体实现见 [架构说明](architecture.md)；检索与存储技术的后续演进需另行评估。

## 9. 每条个人记忆需要保留的边界

建议字段：

- 世界与所属 NPC ID，记忆 ID，内容版本。
- 来源事件或消息 ID、发生时间与实际获知时间。
- 涉及人物与对象；作者、行为者、对象不能混为同一个角色。
- 获取方式：亲见、亲历、他人告知、推断或主观解释。
- 可见范围、分享限制，以及该 NPC 实际知道的部分。
- 情绪意义、人物关联、重要性、当前有效性。
- 是否关联未履行承诺、剧情条件或受保护关系。
- 上次自然回想或实际使用时间、衰减状态与压缩来源。
- 被哪些新证据更新、否定或取代。

“我听乙说甲搬走了”不能压缩成“甲搬走了”。多个人重复同一传闻也不自动提升为已确认事实。

记忆检索以世界和 NPC 为硬过滤条件。不能先搜索全世界所有人的私有记忆，再要求模型自己保密。

## 10. 记忆写入与检索

### 10.1 写入

只有实际发生并被该 NPC 获知的内容才能进入个人事件记忆。生成草稿、未实际传达的消息、未执行的计划不能作为完成事实写入。

一次事件对不同人物可以形成不同记忆：救助者记住自己的付出，被救者记住经历，旁观者只记住其看见的部分。关系效果由游戏规则另行结算，不在检索或摘要时再次添加。

保存“某人说过某句话”与保存“这句话的内容是真的”是不同操作。蓄意说谎、误会、传闻若进入玩法，需要保留这种区别。

### 10.2 检索顺序

建议先获取本轮必需内容，再分配可选记忆预算：

1. 当前问题、有效承诺、规则必须提供的人物定义和约束。
2. 该人物可见的近期会话历史。
3. 与当前人物、事件、话题、地点有关的情景记忆。
4. 有来源的长期认识、情绪意义和适用的节日记忆。
5. 在预算允许时补充的低优先级细节。

相关性、新近程度、重要性、未完成事项与上次使用情况共同决定排序。不会仅按最新排序，也不会因为一条记忆“情绪强烈”而每轮重复注入。

本轮检索与后续表达需分别控制：模型收到一条记忆，不代表应在台词中复述它。可以通过态度或选择体现记忆。

### 10.3 反复回想的限制

仅仅被程序检索到，不自动增加重要性或延缓遗忘；否则会形成“常被搜到所以永远重要”的循环。

真实的新经历、主动回忆、实际谈论或剧情回访可以按规则强化记忆，但需要独立事件来源、去重与上限。相同台词刷屏不能无限强化关系和记忆。

## 11. 记忆压缩

压缩的目标是减少上下文占用并保留因果和身份，不是把一切整理成更好听的故事。

### 11.1 触发与分组

- 会话结束、记忆数量或实际上下文长度达到门限时触发整理。
- 对事件、话题或同一段会话分组，不将无关人物与日期直接拼成一段。
- 只处理明确的来源范围，并保留压缩截止点；新到消息不丢失，也不反复归入旧批次。
- 在独立预算下调度压缩，避免抢占当前玩家对话；后台计算也必须绑定世界代次和来源版本。

### 11.2 必须保留的信息

谁做了什么、对谁做、何时发生、实际结果、信息从哪里来、哪些仍不确定、哪些是承诺而非完成，以及哪些细节不能让其他人知道。

可选的重要原话可以单独保留，但不要求永久保留所有措辞。摘要分为可核对的事实部分与明确标记的主观解释，不能相互替代。

### 11.3 提交与质量检查

1. 建立带版本与来源 ID 的压缩任务。
2. 生成候选摘要，保留覆盖的来源集合。
3. 校验人物、时间、否定、承诺状态、传闻来源和可见性是否被改变。
4. 在来源仍有效时提交新版本，再按保留策略处理旧文本。
5. 失败时保留现有可用数据，不用坏摘要替换原文；必要时采用确定性的事件字段摘要。

结构校验不能保证语义完全正确，需要使用实际对话样本评测。重要承诺与任务状态优先使用游戏结构化记录，不由模型摘要推断。

避免长期只对上一版摘要反复摘要。关键主题应能回溯到保留的结构化事件和必要证据，减少人物串位、遗漏否定和将猜测写成事实的累积失真。

## 12. 遗忘、衰减与归档

### 12.1 分清四种变化

| 变化 | 含义 | 不应该造成的结果 |
|---|---|---|
| 压缩 | 用更短表达保留信息 | 不把含糊说法升级为事实 |
| 降权 | 降低平时想起的概率或检索优先级 | 不自动撤销关系与行为后果 |
| 认知遗忘 | 角色不再能访问某些细节，只保留概要或完全失去该条可用记忆 | 不因底层仍有归档就偷偷把细节重新塞给角色 |
| 物理清理 | 根据容量策略删除或合并原始文本、索引 | 不删除仍被任务、承诺或有效摘要依赖的唯一证据 |

### 12.2 建议保留策略

- 普通寒暄和重复小事：较快降权、合并，必要时清理原话。
- 一般共同活动：保留概要与人物关联，细节可以逐渐减少。
- 救助、重大冲突、关键转折：保护因果与关系节点，具体长期保留范围由内容定义。
- 未履行承诺、当前任务与待回答的重要问题：活跃期间固定保留；结束后按结果转为历史。
- 固定身份与游戏权威状态：不参与普通记忆遗忘。

重要性不应只由模型自由给分。游戏事件标签、与自身的关联、实际后果、内容规则和有界的模型判断可以组合，模型输出只是其中一个输入。

### 12.3 遗忘后的表现

角色可能记得“你以前帮过我”，却不记得具体哪一天；也可能只保留好感而说不清全部细节。没有证据时可以表达不确定，不编造精确日期或对白补空白。

这只是候选表现方式。首版若尚不能可靠区分概要与细节，应先实现可控降权和明确缺失，避免宣称已经具备完整的人类式遗忘。

新证据可以重新建立一条有来源的知识。旧细节若已标记为不可访问，单纯检索归档不能自动“恢复记忆”；若要支持提醒后想起，需要定义可回想的概要、提示条件和实际回想事件。

### 12.4 物理清理与来源依赖

原话删除前检查活跃承诺、摘要与事件的依赖。可以保留最小结构化事实与来源标记，明确原文已不可用；不能留下声称能查原话、实际没有来源的引用。

检索索引和缓存随清理、撤销与版本更新同步失效。备份和调试归档不是角色记忆检索的后门。

## 13. 关系、情绪与性格如何利用记忆

记忆影响“想起什么、怎样理解和回应”，关系系统保存已经确认的评价和关系类型，两者协作但不互相冒充。

- 一次帮助可以留下记忆，并由规则改变受助者对帮助者的评价。
- 回想这次帮助不会再次自动增加同一份好感。
- 情绪影响本次语气、回应意愿与注意重点，但不能随意改写固定经历。
- 长期认识应标记依据，遇到反例可以修订；不能因为一句话就认定某人“永远自私”。
- 遗忘某次争执的原话，不意味着相关关系立即恢复。
- 暂时的节庆热情不自动成为永久性格变化。

具体的关系数值、衰减曲线与人格演化不在本文定死，需要内容目标与试玩支持。

## 14. Hooks：节日、事件与个体状态

### 14.1 允许扩展的内容

| 扩展槽位 | 示例用途 | 权限边界 |
|---|---|---|
| 公开背景 | 当前正在举行的节日与活动阶段 | 必须对应实际游戏状态，按知情范围提供 |
| 会话话题 | 鼓励讨论当前活动、一次已经发生的共同经历 | 不强迫每个 NPC 发言，不生成未发生事实 |
| 人物私有片段 | 某人参与筹备的经历、个人回忆 | 只进入有资格知道的角色输入 |
| 表达风格 | 节日问候、允许的临时语气 | 不覆盖固定身份和硬规则 |
| 发言意愿修正 | 对活动感兴趣的人更容易加入话题 | 返回受限的评分修正，不绕过资格、冷却和世界预算 |
| 记忆检索偏好 | 增加同类节日经历的相关性 | 只排序本来可访问的记忆，不解除遗忘或知情限制 |

发言意愿与记忆检索偏好槽位采用结构化、有限范围的配置或返回值，不靠一句提示词直接改变调度概率。

### 14.2 生命周期与隔离

每个 Hook 有稳定 ID、提供模块、版本、作用域、生效条件、有效时间、事件实例、优先级、预算和撤销方式。

作用域明确到世界、场景、会话或人物。使用游戏日历的节日随游戏时间推进；若使用现实时间，需另行声明。个性化 Hook 内容不能放进跨人物或跨世界共享缓存。

同槽位可并存片段按稳定顺序组装；互斥项按优先级选择并记录。高优先级只影响允许扩展的位置，不能覆盖身份、事实、输出契约、权限或知情过滤。

### 14.3 与记忆的关系

Hook 的存在不自动成为 NPC 经历。“今天是某节日”是当前背景，NPC 实际参加活动后才形成参与记忆。节日结束后撤销当前背景，但真实经历可以进入长期记忆。

模型生成期间 Hook 被撤销、事件结束或来源改变时，检查该轮依赖，丢弃或重新生成已失效的内容。不能让节日结束后的迟到回复继续发放奖励或描述活动仍在进行。

可选氛围 Hook 失败可以跳过；必需约束缺失则该轮回退。限制提供器执行时间与输出长度，避免一个扩展阻塞整个群聊。

## 15. 核心输入输出与状态记录

| 交互 | 输入重点 | 输出重点 |
|---|---|---|
| 发言机会评估 | 会话状态、角色资格、性格参数、近期发言与话题状态 | 候选意愿、被选者或无人发言、原因与机会 ID |
| 角色生成 | 绑定身份、该角色可见历史、检索记忆、Hooks、允许能力 | 单个角色台词、目标、回复对象、表情、受限意图；允许有意义的拒绝或沉默反馈 |
| 发言提交 | 候选回复、会话版本、来源和 Hook 依赖 | 实际消息、实际接收者、规则效果及失败原因 |
| 记忆写入 | 已发生且获知的消息与事件 | 个人记忆、来源、可见性、关联承诺及去重结果 |
| 记忆压缩 | 明确来源集合、截止点、角色视图与版本 | 候选摘要、来源覆盖、检查结果与新版本 |
| 遗忘维护 | 游戏时间、状态、保护项与容量策略 | 降权、概要化、不可访问或物理清理记录 |

记录模型版本、提示词内容版本、有效 Hook 版本、记忆来源和轮次等调试信息；不要求保存或展示模型内部推理。用于调试的选择原因可以来自规则评分与可见依据。

## 16. 保存、恢复与预算

- 保存会话已确认消息、个人记忆版本、承诺、发言冷却与必要调度状态。
- 世界读档或恢复时更新运行代次，取消旧模型回复和旧压缩任务的写入资格。
- 压缩与索引后台任务只处理明确快照；提交时同时检查世界代次和来源版本。
- 独立世界离线或闲置时，不通过后台群聊推进关系、知识、话题或遗忘时间。
- 不把尚未传达的生成草稿记为 NPC 经历。
- 相同请求或消息重复送达时，复用结果，避免重复记忆和关系效果。
- 上下文设置总预算，分别限制近期对话、检索记忆、Hook 片段与输出；不能只限制条目数。
- 给自主聊天、当前玩家对话、压缩维护分别设置调度预算，避免 NPC 闲聊占满全部模型服务。
- 当前玩家对话可优先，自主聊天可延后或结束；服务忙碌不应被永久写成角色性格变化。

人数上限、机会间隔、概率范围、记忆容量、压缩门限与并发数需要通过实际模型与部署验证确定。此处不使用未经测试的具体数值作为承诺。

## 17. 表现示例

以下是说明性场景，不是新增的固定 NPC 设定。

| 场景 | 期望表现 |
|---|---|
| 健谈甲、拘谨乙、安静丙在一起 | 甲可能先开口；乙先听；丙在熟悉的话题上补充，比例不必平均 |
| 乙连续听了几句，甲问乙的意见 | 乙获得优先回应机会，可以简短回答，不机械等待更多轮次 |
| 乙与陌生人交谈变为与熟人独处 | 发言意愿可能提高，但基础性格与原有经历保持连续 |
| 丙很懂种植，大家谈到作物 | 话题相关性提高丙的参与机会，不使其知道未亲见的别人农田情况 |
| 甲刚刚说过一段往事 | 短期降低重复讲述倾向，不因为检索命中就再讲一遍 |
| 乙曾被甲救助，细节已经淡化 | 仍可以保留感谢与关系后果，无法确认的细节不编造 |
| 节日中甲是筹备者，乙只是参与者 | 甲具有自己的筹备记忆；乙只知道公开信息和实际收到的讲述 |
| 节日结束 | 活动 Hook 失效，人物性格修正解除；实际参加过的经历仍可回想 |

## 18. 验收与观察指标

以下为目标验收维度，不表示所有场景均已验证。当前自动化验证范围及运行方式见 [测试与验证](testing.md)。

| 类别 | 需要验证的情况 |
|---|---|
| 群聊身份 | 无玩家的三 NPC 会话可以成立；同名、改名不串角色；模型不能代别人说话 |
| 知识归属 | 接收者、旁听者、离场者与迟到者得到不同且正确的历史 |
| 人格差异 | 在相同话题和关系条件下，多次机会能表现出不同的主动率与接话倾向 |
| 情境变化 | 怕生者在熟人前、安静者在擅长话题上有合理变化，不永久改写性格 |
| 自然节奏 | 允许沉默和结束，既无健谈者无限霸占，也无强制轮流发言 |
| 直接回应 | 被问者能回答、拒绝或给出沉默反馈，玩家不被概率机制卡住 |
| 时间与概率 | 帧率变化不改变发言机会数量；同一机会重试不重新抽样 |
| 压缩准确性 | 人物、日期、否定、传闻来源、承诺与完成状态不会被混淆 |
| 压缩失败 | 不用坏摘要替换有效记录；来源版本变化时拒绝旧结果 |
| 记忆强化 | 普通检索不自动强化记忆；重复事件不反复结算关系 |
| 遗忘边界 | 细节遗忘不撤销物品、关系与承诺；归档不偷偷恢复禁止访问的细节 |
| 重要记忆 | 活跃任务和承诺不会被普通容量清理移除 |
| Hook 生命周期 | 私有片段隔离，活动结束、撤销、读档后不残留旧上下文 |
| 暂停恢复 | 自主聊天和长期遗忘不在离线推进；正式对话可以在暂停中继续轮次 |
| 预算与降级 | 多场闲聊、压缩与玩家对话并存时有界调度；超时不导致无限重试 |

建议记录：各类发言机会与成功发言次数、主动率、接话间隔分布、连续霸占次数、重复话题次数、直接问题响应结果、压缩前后长度、来源保真问题、上下文占用与调用耗时。

发言效果需要在多组场景与多次抽样下评估，不能用一次“三轮后发言”的演示证明机制有效，也不以所有人的发言比例接近作为目标。

## 19. 后续设计与评估重点

在现有原型基础上，需要继续评估以下内容：

1. 首版使用哪些性格维度与动态状态，以及内容作者如何配置。
2. 发言机会如何产生，直接问题、沉默与结束如何展示。
3. 哪些记忆必须长期保护，哪些允许只留概要或真正遗忘。
4. 压缩与摘要的结构、检查方法和失效恢复。
5. 首批 Hook 槽位与一组用于验证的节日或特殊事件。
6. 用少量固定 NPC 的对照场景验证效果，再确定数值和性能限额。

本文记录目标、边界与候选机制。已有实现以 [架构说明](architecture.md) 和 [接口与状态契约](contracts/agent-state-v1.md) 为准；体验、参数与容量仍需持续评估，不能将本文视为完整能力已通过验收的承诺。
