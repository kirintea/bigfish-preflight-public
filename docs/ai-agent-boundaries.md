# 游戏 AI-Agent 接入与能力边界

初稿日期：2026-11-14。公开修订：2026-11-15。

## 1. 文档范围与产品假设

本文描述游戏与 NPC Agent 之间的职责、权限、输入输出及一致性要求，为能力扩展与验收提供设计依据。

产品采用单人独立世界，支持固定 NPC、受模板约束的行为，以及预设选项与自由输入结合的对话。正式对话暂停世界时间；离线与闲置场景需要暂停和保存。多 NPC 群聊可以没有玩家参与，“多人”指会话参与者，不改变单人独立世界的定位。

设计要求隔离角色的发言、关系、知识与记忆，并通过有作用域和有效期的 Hooks 提供特殊事件、节日等上下文。

群聊、性格驱动的发言意愿、记忆压缩与遗忘、事件 Hooks 的细化设计见 [NPC-Agent 核心设计](npc-agent-conversation-memory-hooks.md)。

**本文包含目标能力、约束与候选方案，不是已实现功能或验收结果清单。** 当前原型已有部分机制；实际模块与持久化边界见 [架构说明](architecture.md)，接口支持范围见 [接口与状态契约](contracts/agent-state-v1.md)，验证范围见 [测试与验证](testing.md)。

## 2. 推荐的接入深度

| 方式 | Agent 的作用 | 判断 |
|---|---|---|
| 只生成台词 | 解释已经发生的事情，所有选择由固定规则完成 | 可以用于基础回退，但不足以覆盖 AI 参与受限决策的目标 |
| 从允许范围中提出意图 | 结合人物、记忆和对话，在合法候选中选择或填写受限参数，游戏规则负责执行 | 推荐作为第一版接入方式 |
| 自主开放规划 | 自行寻找工具、连续规划、生成任务甚至定义新规则 | 当前不采用；范围和验证成本尚无明确边界 |

第一版建议以一个 NPC 的一次发言轮次提出至多一个有实际后果的意图为起点。同一群聊可以包含多个 NPC、多个轮次，并不受“整场只允许一个意图”的限制。复杂任务可以由一个预设任务模板承载，内部多步执行由游戏负责。

## 3. 职责与权威状态

建议由服务端游戏规则维护权威世界状态；浏览器处理显示与操作。具体渲染、移动反馈和网络同步设计另行确定。

| 部分 | 负责 | 不授予的权限 |
|---|---|---|
| 浏览器界面 | 移动与交互输入、对话、选项、立绘、等待和结果显示 | 不自行确认货币、物品、关系或剧情已变更 |
| 游戏规则与模拟 | 人物和物品状态、时间、任务、关系、行动执行、存档、权限检查 | 不把模型自然语言当成已经执行的事实 |
| 接入协调层 | 绑定世界与人物身份、组装上下文、管理请求与对话轮次、校验输出、调用规则并回传结果 | 不允许模型替换请求所属的世界、玩家或 NPC |
| AI-Agent 服务 | 模型调用、人物表达、受限意图选择、记忆检索与摘要、异常回退 | 不直接写游戏权威状态，不执行模型生成的代码或任意外部工具调用 |
| 内容定义 | 固定人物背景、可变范围、行为模板、剧情条件、对话选项、效果规则 | 不以一句提示词代替实际权限与规则校验 |

接入协调层可以与游戏后端部署在一起，或采用独立服务；无论采用哪种形态，身份与执行权仍由可信的游戏后端控制。

## 4. 能力接入清单

能力由游戏提供并登记，Agent 只能使用当前请求显式开放的部分。下列名称用于说明职责，不是已确定的函数名。

| 能力 | 游戏提供的输入或条件 | Agent 可返回 | 实际效果的决定者 |
|---|---|---|---|
| 人物对话 | 已知事实、人格、关系、当前话题 | 台词、允许的表情或语气标签 | 接入层检查表达，游戏决定状态效果 |
| 多 NPC 群聊 | 会话成员、指定发言者、该发言者可见历史、有效接收者 | 当前发言者的一轮回复、指向谁及受限意图 | 会话协调器管理顺序，游戏确认实际传达、知识和关系效果；玩家可不参与 |
| 提示词 Hooks | 当前有效事件、节日、人物与场景条件 | 注册的内容提供器返回有来源、作用域和有效期的上下文片段 | 协调层过滤并组装；Hook 不直接改变世界规则或角色权限 |
| 预设选项 | 剧情与条件筛选后的选项 | 可选的自然语言表述 | 选项对应的规则或任务分支 |
| 社交回应 | 可用回应类别及其限制 | 接受、拒绝、感谢、安慰等允许的语义选择 | 游戏按关系、历史和冷却结算，Agent 不返回任意好感增量 |
| 承诺与任务 | 可用任务模板、有效目标、允许条件 | 从模板中提出或接受一个约定 | 游戏记录承诺，之后记录履行、取消或失败 |
| 人物行动意图 | 当前人物有资格尝试的行为与目标 | 从候选中选择意图 | 游戏检查、调度、寻路并执行 |
| 商店交互 | 商品、库存、价格、交易规则 | 解释商品、建议打开购买界面 | 玩家明确的交易操作与游戏规则；默认不因闲聊自动扣款 |
| 消息传播 | 可传播事实、来源、渠道与接收者条件 | 提议讲述某件已知事情 | 游戏确认交互发生后更新接收者知识 |
| 记忆维护 | 已确认事件、可见对话与来源 | 摘要、索引与主观解释 | 权威事件仍由游戏保存；摘要不能改写事实 |
| AI 叙事者 | 可触发的事件模板、条件、预算与节奏 | 选择事件模板及允许参数 | 游戏验证并执行；是否纳入首版另行决定 |

基础种植、睡眠、库存计算、家具摆放检查、商店结算与救助兜底不依赖模型成功返回。NPC 日常执行也不能要求每一步都调用模型。

“可以提出某项能力”不表示游戏已经实现该能力。未提供执行器、结果和验收场景的能力不开放给 Agent。

## 5. 每项能力必须具备的契约

接入一项新能力前，需要共同填写：

| 项目 | 必须说明的内容 |
|---|---|
| 标识与版本 | 稳定能力 ID、契约版本、适用内容版本 |
| 调用身份 | 哪种 NPC、剧情角色或叙事者可以使用 |
| 前置条件 | 地点、关系、任务阶段、资源、身体能力和有效目标 |
| 参数 | 类型、范围、可选实体、数量上限；不接受任意字段 |
| 时间语义 | 对话中可立即结算，还是需要世界恢复后执行 |
| 玩家参与 | 是否需要玩家选择、接受条件或确认交易 |
| 效果 | 哪个游戏规则执行、改变什么状态、哪些状态不能改变 |
| 生命周期 | 受理、等待、执行、成功、失败、取消和过期 |
| 结果与可见性 | 结果事件、失败原因、谁能知道、哪些信息能展示 |
| 重复与恢复 | 重试如何返回同一结果，存档、读档后如何恢复或作废 |
| 验收 | 正常执行、条件不满足、中断、重复与旧请求的实例 |

## 6. 游戏传给 Agent 的输入

输入分成可信请求信息与经过过滤的角色上下文。自由输入文字始终属于玩家话语，不能改变权限或替换系统定义。

| 输入组 | 建议字段或含义 | 边界 |
|---|---|---|
| 请求定位 | 契约版本、请求 ID、世界 ID、世界运行代次、对话 ID、轮次 ID、指定发言者 ID、成员版本、已提交消息序号 | 由服务端绑定；模型回传的同名字段不作为身份依据 |
| 有效期 | 真实时间截止点、游戏时间、相关对象版本 | 模型等待按真实时间超时；不因游戏暂停而无限等待 |
| 轮次触发 | 玩家文字或选项、已传达的 NPC 发言、已发生的事件或获准的话题触发 | 不要求存在玩家输入；触发者身份明确，不能把 NPC 台词伪装成玩家命令 |
| 会话成员与历史 | 参与者 ID、可见称呼、加入退出状态、消息作者、目标、回复关系与实际接收情况 | 名字只用于显示；每个发言者只收到其可见历史，不汇总所有人的私密记忆 |
| 固定人物定义 | 角色 ID、固定背景、表达方式、不能改写的事实 | 版本化内容；对话不能任意重写出生背景、职业等硬设定 |
| 可变人物状态 | 当前任务、情绪、关系、允许变化的目标 | 只提供本次决策需要的信息 |
| 角色知识 | 亲见事实、听闻信息、来源、时间、不确定性 | 角色不应收到其无权知道的完整世界存档 |
| 相关记忆 | 已确认事件引用、摘要、当前仍有效的承诺 | 严格绑定世界与人物；过期摘要不能覆盖新事实 |
| 能力与候选 | 当前可用能力、候选 ID、合法目标与参数范围 | 候选提供时合法，不代表执行时一定仍合法 |
| 输出限制 | 允许字段、文本长度、枚举值、最多意图数等 | 由协调层校验，不只依赖提示词 |
| Hook 快照 | 有效 Hook ID、版本、事件实例、有效期及经过知情过滤的片段 | 不能仅凭节日或事件标签向所有参与者公开秘密；提交时检查依赖仍有效 |

推荐第一版由协调层直接提供足够的受限上下文。后续若增加 Agent 主动查询工具，每次查询仍独立执行身份和知情过滤，并设置调用次数与数据量上限。

## 7. Agent 返回的输出

完整结构化结果必须通过校验后才能成为确认回复。流式接口可以先展示临时文本增量，但增量不是提交回执，不能据此结算动作、关系或记忆；失败时界面需区分临时文本与最终结果。

| 输出 | 含义 | 不能替代什么 |
|---|---|---|
| `utterance` | NPC 拟说出的台词 | 不代表物品已交付、任务已完成或世界事实成立 |
| `recipient_ids` | 本句指向的允许接收者，可由协调器展开“全体” | 不等于这些角色都实际听到了；不能借此控制接收者行为 |
| `reply_to_message_id` | 所回复的已传达消息 | 只能引用当前发言者可见且有效的消息 |
| `expression_id` | 从允许列表中选择的表情 | 不自动修改人物情绪数值 |
| `intent` | 一个候选能力、候选目标与允许参数；也可以为空 | 不等于动作已受理，更不等于执行成功 |
| `basis_refs` | 用到的输入事实或事件引用 | 引用存在也不自动证明生成内容正确 |

发言者身份由本轮可信请求绑定。若输出包含 `speaker_id`，只允许与绑定值一致；Agent 不能在台词字段中生成多个人轮流发言并让系统据此创建多条角色消息，也不能代玩家作出选择。

预设选项默认来自内容与规则。AI 动态推荐回答属于可扩展能力，是否进入首版另行确定；不能由模型临时创建没有执行定义的关键剧情分支。

模型不得返回任意状态补丁、任意好感增量、凭空生成的物品或角色、未登记的能力、数据库查询或可执行代码。未知字段、无效实体和非法枚举由协调层拒绝。

完整自然语言是否符合事实仍需要实例评测，不能仅凭结构化校验承诺没有幻觉。关键成功反馈由实际结果生成；缺少依据时使用保守回复或回退。

## 8. 游戏返回的执行结果

执行结果由游戏产生，再提供给界面和必要的后续 Agent 请求。

建议结果至少包含：原请求 ID、意图 ID、动作 ID（如已创建）、当前状态、机器可读原因、结果事件 ID、允许透露的实际变化与相关对象版本。

状态约定：

- `rejected`：请求未被受理，如能力未开放或目标无效。
- `accepted`：已经受理，但尚未完成。
- `queued`：等待恢复运行、时机或必要资源。
- `running`：正在执行。
- `succeeded`：效果已经提交，可据此表达成功。
- `failed`：已受理但未能完成；需同时报告是否有阶段性消耗。
- `cancelled`：显式取消，释放该释放的预约。
- `expired`：有效期、对话轮次或世界运行代次已失效。

立即完成的交互可以直接返回成功；耗时行为必须有后续终态结果。`accepted` 和 `queued` 均不能显示成“已完成”。

同一个请求重复到达时，返回已有受理记录或结果，不再次扣资源或增加关系。状态变更、结果事件与去重记录需要一致提交。当前实现使用单机世界聚合提交，具体保证与限制见 [架构说明](architecture.md)。

## 9. 对话、暂停与执行顺序

这里提出一项需要玩法确认的细化：**玩家参与的正式对话暂停世界时间，但允许本次对话的语义结果被确认。** 否则对话无法形成承诺或影响关系。NPC 自主群聊采用第 10 节的运行规则，不自动进入玩家正式对话模式。

| 事件 | 建议处理 |
|---|---|
| 正式对话开始 | 记录此前运行状态，并增加对话暂停原因 |
| 玩家选择或输入 | 生成新的轮次，提供过滤后的上下文和合法候选 |
| Agent 回复 | 校验身份绑定、轮次、内容结构、能力和当前条件 |
| 确认感谢、拒绝或承诺 | 可在暂停时结算本次社交交互、记录承诺；不推进饥饿、作物或移动时间 |
| 提出带路、劳动、取物等行动 | 可登记意图，待世界恢复后执行；执行前重新检查 |
| 结束对话 | 只解除本次对话暂停；此前手动暂停仍保留 |
| 对话中离线或长时间无操作 | 保存并保留相应暂停原因，未提交的模型请求失效 |
| 返回游戏 | 按恢复规则重新建立上下文；旧回复不得自动提交后果 |

建议暂停由多个独立原因共同控制。结束对话不得清除离线或闲置产生的暂停。离线恢复是否要求点击“继续”是交互细节，仍需确定。

玩家正式对话暂停期间，该正式会话内的多个 NPC 可以按轮次回应；会话外的 NPC 自主群聊、叙事者事件和后台行动不继续推进。真实时间上的模型推理可以结束，但提交必须再次验证世界、会话模式和请求是否仍有效。

为避免多意图部分成功的歧义，第一版建议每个 NPC 发言轮次只处理一个有状态后果的意图；对应的关系变化、承诺与事件由同一游戏规则定义。NPC 台词应在结果确定后与受理或拒绝状态匹配。

## 10. 多 NPC 群聊：身份、轮次与传达

### 10.1 会话是独立对象

玩家是可选参与者，不是创建会话的必要条件。允许 NPC 甲、乙、丙自行交谈，也允许玩家加入、退出或旁听已有交谈；具体加入方式属于后续交互设计。

建议会话记录包含：`world_id`、运行代次、`conversation_id`、模式、位置或通信渠道、发起者、成员及成员版本、消息序列、当前发言轮次、暂停与结束原因。玩家参与者 ID 可以为空，所属世界 ID 始终存在。

每条实际发言单独记录：`message_id`、会话内序号、作者 ID、指向的接收者、回复消息 ID、游戏时间、实际接收者、正文、来源与关联意图。NPC 名字和昵称只用于显示，同名、改名不改变身份。

“对乙说话”“丙也听到”“玩家界面能看到气泡”是三个不同判定。游戏在发言提交时确定实际接收者，包括有资格听到的旁观者；不因为同在参与者列表就自动授予所有历史与知识。开发者查看完整日志，也不表示玩家角色知道其内容。

### 10.2 建议逐个发言者生成

建议采用“一个会话协调器 + 每轮指定一个发言者”的方案：

1. 游戏根据发起事件、被提问者、参与状态和发言机会选择下一发言者，也允许会话自然结束或角色不回答。
2. 只给该发言者自己的固定设定、私有记忆、可见群聊历史和本轮候选能力。
3. Agent 只返回这个人物的一轮发言及意图；协调器校验身份、接收者与回复关系。
4. 游戏确认发言实际发生和传达对象，记录唯一消息及允许的效果。
5. 其他角色下一轮才能引用自己实际收到的这条消息。

不把多名 NPC 的私密记忆合并给一次“全员扮演”请求作为默认方案。后续即使增加多句批量生成，也必须逐句保留身份、可见性与失效校验，不能把尚未发生的后续台词提前记为事实。

### 10.3 避免串话和错误归属

- 每个会话同一时间只有一个有效生成轮次；不同世界与互不冲突的会话可以独立调度。
- 建议每个 NPC 同一时间只参与一个正在生成发言的主动会话，避免同时在两处承诺不同事情；会话优先级和转入规则由协调器管理。
- 成员加入、退出、移动离场、无法说话、世界暂停或模式变化时，更新相关版本并使不适用的待提交回复失效。
- 迟到者只收到加入后实际听到的内容；需要补述时由其他角色真实转述，来源仍保留。
- 待生成、已生成但未传达、已实际传达分别处理。只有实际传达的消息进入接收者记忆。
- NPC 甲对乙的请求不能直接控制乙。甲只能表达请求；乙的回应或行动由乙自己的轮次与规则确认。
- 关系效果明确方向与目标，例如乙对甲的评价；旁听者可能有自己的反应，但不默认给所有人同样的增减。
- 一条发言使用唯一消息 ID；其对不同角色的知识记录和关系效果分别去重。传播一次消息不会无限触发相同回应或重复增加好感。
- 加入轮数、持续时间、话题冷却和世界级调用预算，防止 NPC 互相触发无限对话；具体数值在性能验证后确定。

### 10.4 群聊与暂停的关系

| 模式或状态 | 建议规则 |
|---|---|
| NPC 自主群聊，世界正在运行 | 不自动暂停整个世界；按调度生成并提交，人物忙碌或离场可中断 |
| 玩家进入正式群聊 | 将会话切换到正式模式，自动暂停；多个 NPC 在会话内按轮次回应 |
| 玩家只在旁边观察 | 不仅因出现气泡自动暂停；是否听到由渠道与位置规则决定 |
| 手动暂停、闲置暂停或离线保存 | NPC 自主群聊停止提交和传播，未提交回复失效或等待重新生成；已确认内容保存 |
| 玩家结束正式对话 | 恢复此前状态并保留其他暂停原因；若 NPC 要继续聊天，需在恢复运行后重新调度 |

这里的“没有玩家”指会话内可以没有玩家，并不取消此前“世界离线、长时间无操作就暂停保存”的规则。若未来希望世界无人在线也持续模拟，需要另行修改世界运行策略。

## 11. 提示词注入 Hooks：特殊事件与节日扩展

### 11.1 注册入口与输出

预留受信任的游戏内容模块注册入口，让特殊事件、节日、场景和人物状态按条件提供上下文。此处的“注入”指项目主动提供的扩展接口，玩家话语和 NPC 生成内容不能自行注册 Hook。

建议提供注册、启用、更新与撤销生命周期。Hook 接收经过授权的只读快照，返回结构化上下文片段；不直接修改世界、发起模型请求或递归触发会话。

| Hook 槽位 | 可提供内容 | 约束 |
|---|---|---|
| 世界与事件背景 | 当前节日、公开活动、已发生事件及阶段 | 来源于游戏实际状态；私人事件仍需逐人过滤 |
| 场景与会话主题 | 当前地点氛围、活动主题、角色正在参与什么 | 限定世界、场景和会话，不能扩大成员或听众范围 |
| 人物私有上下文 | 某人的节日回忆、职责、当前可知任务 | 仅进入指定人物的轮次；不能经共享缓存进入其他人物上下文 |
| 表达偏好 | 节庆问候、临时语气、允许的表达素材 | 不覆盖固定身份、真实事实、知情规则或输出契约 |

第一版优先支持数据与文本片段式扩展。若使用程序化提供器，其代码来自项目部署流程；不执行玩家或模型提交的任意脚本。

### 11.2 每个 Hook 的元信息

| 字段组 | 需要表达的内容 |
|---|---|
| 身份与来源 | `hook_id`、提供模块 ID、定义版本、关联事件实例及事实引用 |
| 作用域 | 世界、场景、会话、人物、会话模式；未指定不能默认变成跨世界全局 |
| 生效条件 | 事件阶段、参与条件、知情资格、游戏日历起止时间 |
| 生命周期 | 启用、更新、撤销、事件结束和读档后重建方式 |
| 组装策略 | 槽位、优先级、追加或互斥组、可替换的自有片段 |
| 预算与降级 | 内容长度上限、是否可选、超时或缺失时的行为 |
| 观测信息 | 本轮实际注入的 ID、版本、跳过或裁剪原因 |

节日默认按游戏时间生效，游戏暂停时不因现实时间流逝而结束；若某活动确实使用现实日期，需要显式声明时间来源与时区。

### 11.3 优先级与权限

- 硬规则、身份绑定、输出契约、真实事实与知情隔离始终受保护，不能被 Hook 的高优先级覆盖。
- 建议在同一可扩展槽位内以数值更大的优先级优先，平级按稳定 Hook ID 排序，保证组装顺序稳定。
- 可并存内容按顺序组合；互斥组只选最高优先级项并记录结果。相互矛盾的事实不能靠拼接多个提示词解决，应拒绝冲突并检查事件状态。
- 普通 Hook 只能追加或替换自己拥有的可扩展片段，不能替换整个系统提示词或别的模块的固定人物定义。
- 节日优惠、礼物、任务开放等实际能力由游戏规则先生成合法候选；Hook 可以解释和引导，但不能单凭文案授权免费物品或新增动作。
- 正文、元信息和引用在注入前与注入后都经过可见性检查；字段合法不等于自然语言一定没有错误，仍需专项评测。

### 11.4 失效、缓存与失败

- 每个请求保存本轮生效 Hook 的版本与依赖快照。生成期间事件结束、Hook 撤销或身份范围改变时，受影响回复不能继续按旧上下文提交。
- 存档保存事件状态与 Hook 定义引用；加载后按当前世界状态重建有效 Hook，不保存一份永久拼接的大提示词作为事实源。
- 个性化上下文缓存必须区分世界、人物、会话、知识视图、事件和 Hook 版本；可共享的只有不含玩家世界状态的静态模板。
- 超出预算时优先裁剪可选氛围片段，保留必需的身份、事实与规则。必需上下文无法提供时使用回退或拒绝生成，不悄悄移除关键约束。
- 可选 Hook 抛错或超时可跳过并记录；必需 Hook 失败则该轮回退。单个节日扩展不能无限阻塞世界。

### 11.5 说明性例子

某个节日活动处于进行阶段，NPC 甲和乙在场内聊天，玩家不在会话中：

- 两人都能得到公开节日背景与本会话已经实际听到的发言。
- 甲作为活动筹备者可以额外收到自己的职责与私人准备经历；乙不自动得到这些内容。
- 若甲在对话中告诉乙一件允许公开的筹备经历，乙在实际收到该消息后才获得这份听闻知识。
- 活动结束后不再注入“活动正在进行”；已发生的聊天和共同经历仍然保留。

此例只说明扩展方式，不新增已经确定的节日、人物或剧情。

## 12. 记忆、关系与信息传播

必须区分以下数据：

- **真实发生的事件**：游戏记录谁做了什么、何时发生、结果是什么。
- **实际说过的话**：表示角色说出了某个主张；其中内容不自动成为世界事实。
- **人物知识**：某角色亲见或听说什么，来源和可信程度如何。
- **主观评价**：人物怎样解释某件事，不覆盖事件本身。
- **关系状态**：方向性的评价、关系类型及其规则来源。
- **模型摘要**：用于检索与压缩上下文的派生数据，不是最终事实来源。

Agent 服务可以维护记忆检索索引，但已确认事件、承诺和关系效果需要随世界保存。摘要带来源事件 ID；来源被回档移除时，对应摘要必须作废或重新生成。

世界 ID 和 NPC ID 都参与记忆隔离。同一个固定人物模板在两个玩家世界中的经历不能混用。共享模型推理不表示共享会话历史或记忆。

消息传播需要真实渠道和实际结果。NPC 提议告诉另一人，不代表对方已经知道；重复传播同一消息也不重复结算同一关系效果。群聊内逐句记录实际接收者属于必要边界；群聊之外更长的传播链是否首版实现，另行确定。

## 13. 存档、迟到请求与恢复

- 新游戏、读档或恢复世界时更新运行代次，使旧运行中的请求不能写入当前世界。
- 保存世界事实、承诺、任务状态、已确认对话与去重记录；不依赖正在运行的模型请求作为存档唯一信息。
- 加载后先恢复游戏权威状态，再重建或校验 Agent 派生记忆。
- 恢复后的同一任务使用既有动作记录，不因为重新生成台词而再次创建。
- 不以“整个世界的每帧版本必须相同”作为唯一有效性条件；检查世界代次、对话轮次及该动作依赖的对象和条件，并在提交时重检。
- 取消请求后可以尝试停止推理；即使推理无法及时停止，返回结果也必须丢弃。
- 已提交效果但回复丢失时，通过已有请求结果恢复界面，不重新执行。
- 保存会话成员、已传达消息、接收者记录与结算结果；恢复后重新验证成员位置与会话条件，再决定继续或结束。未传达的草稿不进入任何人物的既成记忆。

## 14. 失败、限额与调试

| 情况 | 建议行为 |
|---|---|
| 模型超时或不可用 | 使用固定人物的保底回应，保留预设选项及基础玩法；玩家可以结束对话 |
| 输出结构错误 | 至多一次受限纠正尝试，并受同一总截止时间约束；仍失败则回退 |
| 意图不合法或条件变化 | 不提交效果，按允许透露的原因解释或提示重新选择 |
| 纯对话无法确认事实 | 使用不确定表达或回退，不编造已执行结果 |
| 服务繁忙 | 限额排队或明确回退，不无限生成后台请求 |
| 服务恢复 | 不自动补执行离线期间失效的意图或事件 |

建议每个会话同一时间只有一个有效模型请求；首版每个 NPC 发言轮次最多一个有实际后果的意图。模型调用期限、输入输出长度、群聊轮数、每世界与服务总并发、队列容量需要配置，并在模型和部署验证后确定具体数值。NPC 自主群聊超时可以跳过本轮或结束会话，不必制造玩家可见的错误弹窗。

联调记录包括：请求与轮次 ID、世界运行代次、会话与成员版本、发言者和实际接收者、内容版本、上下文来源 ID、生效 Hook 与版本、模型配置标识、耗时、校验结果、动作结果和回退原因。日志不得包含模型密钥；开发调试记录不直接暴露给玩家。

## 15. 一个建议的完整实例

玩家对某 NPC 说：“等会儿带我去商店吧。”此例仅验证能力边界，不新增具体人物或剧情设定。

1. 游戏已提供当前可尝试的“带路到商店”任务候选；NPC 知道地点且拥有相应能力。
2. Agent 根据性格、关系和任务状态选择接受、拒绝或允许范围内的替代方案。
3. 若选择接受，游戏检查条件并登记带路任务，返回“已受理、等待恢复”。
4. NPC 可以说“好，聊完我带你过去”，不能说“我们已经到了”。
5. 对话结束且没有其他暂停原因后，游戏执行带路；障碍、改道与中断由游戏处理。
6. 到达后游戏记录完成事件，Agent 后续可以引用这次经历。
7. 若玩家在等待回复时离线，该回复失效，不产生新任务；若任务在离线前已受理，则按保存的任务状态恢复，而非重复创建。

## 16. 接口验收场景

以下是未来实现的验收要求，不是已经执行的测试。

| 场景 | 预期结果 |
|---|---|
| 普通自由对话 | 不带意图时不擅自扣款、发物品或推进任务；对话记录与规则明确的社交效果可分别处理 |
| 合法社交回应 | 经规则确认后产生一次可追溯的关系效果 |
| 角色不知道某件秘密 | 输入视图中无该秘密，不能通过查询绕过知情边界；回答另做事实与泄漏评测 |
| 玩家文字要求改写权限 | 仍按原能力清单和身份处理 |
| 不存在的能力或目标 | 明确拒绝，世界状态不变 |
| 带路等耗时动作 | 暂停时不移动，恢复后执行，完成后才报告完成 |
| 重复提交或网络重试 | 复用已有请求记录，不重复提交效果 |
| 离线、闲置或结束对话后迟到回复 | 不在失效上下文中执行 |
| 读档前的旧回复 | 被世界运行代次检查拒绝 |
| 资源或位置已变化 | 执行时重检并返回真实结果 |
| 同模板 NPC 位于两个世界 | 记忆、关系、任务和上下文互不混用 |
| 模型故障 | 玩家能退出对话并继续基础玩法，不因模型故障停留在无法解除的等待状态 |
| 承诺与实际完成不同 | 能分别引用承诺、履行或失败，不把承诺记为已完成 |
| 三名 NPC 群聊且玩家不参与 | 可以创建会话、调度发言与结束，不需要伪造玩家消息；群聊本身不自动暂停世界 |
| 同名或改名 NPC | 通过稳定 ID 区分，台词、意图与关系不归到另一个人 |
| 甲问乙，丙旁听 | 明确作者甲、目标乙及实际接收者；丙的知识与评价独立结算 |
| 甲知道秘密，乙不知道 | 乙的生成请求不含甲的私密记忆；只有实际且获准的转述才能改变乙的知识 |
| 成员中途加入或退出 | 后续请求更新成员版本，迟到回复失效；加入者不自动获得加入前的历史 |
| 模型代其他 NPC 或玩家发言 | 身份不匹配的结构化输出被拒绝；文本冒充需评测与回退，不转换成他人已说的话 |
| 消息尚未实际传达 | 接收者记忆和关系不提前结算，重试也不重复传达同一消息 |
| 玩家正式群聊中另一处 NPC 闲聊 | 正式会话内可继续轮次，外部自主会话停止推进 |
| 节日 Hook 启用与撤销 | 只影响正确世界、人物和阶段；结束后不继续把节日描述为正在进行 |
| NPC 私有 Hook 与共享缓存 | 私有片段不进入其他角色或其他玩家世界的输入 |
| 高优先级 Hook 要求绕过规则 | 无法新增权限、覆盖身份、泄漏秘密或直接修改库存 |
| Hook 冲突、超时或超长 | 确定性选择或明确回退，记录原因，不悄悄裁剪必要限制 |
| Hook 变化或读档时模型尚未返回 | 旧依赖的回复不提交；从恢复后的事件状态重建 Hooks |
| 自主群聊持续互相回应 | 受轮数、时长、冷却和调用预算限制，能够正常结束 |

## 17. 能力扩展前的关键选择

扩展能力时，建议依次检查：

1. 权限是否仍限制在合法候选中的受限意图。
2. 暂停中可确认的语义结果与恢复后执行的耗时行为是否有明确区分。
3. 群聊是否保留逐发言者生成、身份与听众隔离，以及 Hook 权限约束。
4. 新增社交回应、承诺或行动模板是否具有真实执行器与结果反馈。
5. 每项能力是否填写第 5 节契约；传播链、动态推荐回答和 AI 叙事者是否需要额外边界。
6. 扩展后的传输、Schema、持久化与数值限额是否经过对应验证。

当前技术选择和接口以公开运行文档为准；本文的候选能力不构成功能清单或排期承诺。

## 18. 设计与实现的对应关系

| 设计主题 | 当前模块 | 阅读重点 |
|---|---|---|
| 权威世界与上报 | `core/game/`、`core/reporting/` | 来源许可、可见性、版本、回执与聚合提交 |
| 角色生成 | `core/agent/`、`core/session.py` | 单角色上下文、候选状态和已确认 AgentState 的隔离 |
| 群聊 | `core/conversation/` | 成员资格、消息送达、发言机会与意愿 |
| 上下文扩展 | `core/hooks/` | NPC 范围、事件依赖、优先级与预算 |
| 个人记忆 | `core/memory/` | 来源、关键词检索、结构化压缩和访问状态 |
| 存档恢复 | `core/saves/` | 聚合快照、校验与运行代次变更 |

模块存在不表示所有目标玩法已实现。当前记忆检索采用关键词和重要性排序，压缩采用结构化规则；通用行动能力中也包含模拟接受结果，不能将其理解为完整物理行动或完整语义记忆系统。具体边界见 [架构说明](architecture.md)。

## 19. 模块调用与提交边界

### 19.1 分层职责

`main.py` 与 `server.py` 负责启动及应用装配；`api/` 负责请求模型、身份校验和传输适配。配置与内容定义位于 `configs/`，玩家运行数据与日志独立保存。

角色生成、世界规则、会话、记忆、Hooks 与存档分别归属各自模块。增加新能力时，应沿用这些职责边界，避免把模型调用、权限判断和磁盘写入集中到路由中。

### 19.2 生成与提交顺序

1. `api/` 从可信访问身份解析世界归属，不以浏览器提供的任意世界或 NPC ID 作为授权依据。
2. `core/agent/turns.py` 协调生成和提交，结合世界可见事实、会话消息、该 NPC 的记忆与有效 Hooks 构造上下文；会话成员与发言调度由 `core/conversation/` 管理。
3. 角色生成器只产出候选回复与受限意图，不直接授予动作权限或写入确认世界状态。查询能力也须经过角色可见性过滤。
4. 协调层校验结构、发言者与依赖，再由规则路径检查意图当前是否可执行。模型等待期间不持有整个世界的长锁。
5. 提交阶段重新检查运行代次及相关版本，确认消息送达、动作受理和规则效果；已获知事件才进入个人记忆。同一请求重试不得重复结算。
6. `core/saves/` 保存世界聚合的一致快照。读档更换运行代次，旧模型和压缩结果即使取消失败，也不得写入恢复后的状态。

### 19.3 文件后端边界

当前 `core/game/repository.py` 以进程内锁保护候选聚合，在同目录写临时文件、flush、fsync 后通过 `os.replace` 替换，再发布确认内存版本。存储根文件锁阻止第二个写入器。

当前部署要求单进程写入，可管理多个隔离世界。扩展到多进程或多实例前，需要先设计世界路由、独占写入与恢复方案；增加 worker 数量不能直接获得这些保证。文件替换与快照的限制见 [架构说明](architecture.md)。

## 20. 测试观测与状态接口

测试环境需要支持按域读取和上报状态，并通过管理测试台设置场景、触发生成、检查回执及故障结果。角色视角接口始终执行可见性过滤，管理接口须使用独立鉴权；测试权限不能扩展角色本身的知识范围。

当前观测包括本地阶段诊断，以及可选的 AgentScope 模型推理 OTLP 导出。不能据此认定所有自定义阶段都已导出为 OTel spans，也不要求展示模型内部推理。配置和本地 Collector 启动方式见 [运行配置](configuration.md)。

接口的精确路由、字段与支持状态见 [接口与状态契约](contracts/agent-state-v1.md) 和运行服务的 `/openapi.json`。通用报告注册表与独立管理测试接口具有不同的支持范围，不能仅凭领域名称推定操作可用。自动化验证及其限制见 [测试与验证](testing.md)。
